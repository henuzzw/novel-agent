## 1. 交付目标

第一轮交付应让作者完成以下操作，并看到各阶段的依据和产物：

```text
选择项目创作策略和写作风格
  -> 大纲中设计前三章短弧及读者期待
  -> 合同明确场景行动、兑现、伏笔和退出状态
  -> 正文直接执行风格、开篇策略与合同
  -> 检查具体问题并选择修订
  -> 保存新稿并复检
  -> 作者确认 -> 正史审稿 -> 正史提交
```

番茄向首章应在开头几个自然段呈现人物及具体问题，章内有行动、阻力和真实进展；第二章承接后果，第三章完成第一轮有铺垫的兑现。效果通过合同检查、正文证据和目标读者连读评估。

## 2. 当前基础与开发边界

| 当前基础 | 本轮要补的内容 |
| --- | --- |
| 故事方向、圣经、大纲及增量调整 | 读者承诺、兑现设计和统一前三章短弧 |
| 大纲 `objective/coreEvent/reveal/endingHook` | 在现有字段中落实章变化、回报及后续问题 |
| 合同 `requiredBeats/requiredReveals/forbiddenFacts/expectedExitState/foreshadowActions/hook` | 场景执行信息、本章兑现依据与未来揭示边界 |
| 前两章正文与合同召回、记忆预算 | 保留前章尾段，补下一章计划和资料来源 |
| 四维质量报告、原文证据校验与选定问题修订 | 承诺兑现与开篇检查、清楚的检查状态和修订范围 |
| 风格预设、样本分析、第一章开头试写 | 试写应用项目开篇策略；完整首章验收与试写验收分别记录 |
| 自动任务、作者门禁、有限 FLUENCY 自动修订 | 复用新增上下文和检查，正确处理过期产物 |
| 全局模型设置、统一结构化模型网关、公共 HTTP 层 | 使用现有入口接入业务；保留模型设置与项目创作策略的独立职责 |

第一轮扩展现有单体应用及分层，不新增框架或强制依赖。合同和大纲保持现有字段类型，新增场景标注可按明确格式显示，旧自由文本继续可读可编辑。机器判断不得依赖中文分隔符或关键词解析成功；解析失败时按普通节拍显示，不能捏造结构化依据。

- [x] 另建完整三章语料，至少包含强情节、关系驱动和悬疑三种短弧；短场景不能替代连读语料。已交付三组每章 200～600 字微型三章，常规长度语料待 B05/B07 扩展。
- [x] 固定圣经、大纲、合同、风格、人物档案及正史输入，登记 Prompt / Schema 版本。已通过真实生成入口离线截取 44 份请求并保存各项 SHA-256。
- [x] 建立对照结果模板：模型与强度、输入版本、调用次数、耗时、可得 usage、人工评价和失败原因。
- [ ] 人工复核初始标签，并在登记实际模型、重复次数与预算后执行当前模板的真实模型基线。未运行时保持 NOT_RUN；不以合成报告或离线测试冒充文学验收。

建议位置：服务端测试资源及独立 `evaluation/` 目录；复用 `PlanningPromptConstraintTest`、`WritingPromptRevisionTest` 等输入覆盖测试。结果中区分自动用例和真实模型生成，不将提示词关键字存在视为文学验收。

验收：同一上下文可以运行当前模板与候选模板，并追溯实际输入及配置；语料含正反例。真实评测仅使用明确选择的现有模型，生成数量和预算在运行前记录。

### B03：保留前章出口和未来边界

- [ ] 由当前已发布大纲确定前章、本章和下一章；跨卷、插叙和末章显式处理。
- [ ] 保留有效前章正文尾段，按段落边界截取；短前章避免首尾重复计入预算。
- [ ] 标明前文来源：有效正史正文、作者确认但未提交正文，或仅已确认合同。缺章保持缺失。
- [ ] 下一章输入仅含相关计划和来源版本，标记为未来；不将未来事件放入人物已知信息或已发生事实。
- [ ] 在合同、合同审阅、正文和质量检查中注入与阶段相符的边界；预算收缩时显示哪些资料被裁剪。

主要位置：[WritingContextService](D:/project/agent/novel-agent/apps/server/src/main/java/com/novelagent/writing/application/WritingContextService.java)、`RecentChapterSummariesTool`、`NovelMemoryContext`、`MemoryBudgetAllocator`、`ContextBudgetPlanner`、`WritingPromptFactory`。

验收：长前章结尾在预算中保留；重复正文不双计预算；末章没有虚构下一章；缺失和来源降级能在上下文中看见；前章或下一章依据改变时报告过期。

### B04：场景行动与读者回报进入合同

- [ ] 主要节拍表达起点、意图、阻力或信息差、行动和结束变化，引用重要依据。
- [ ] 大纲与合同明确承诺、铺垫、本章兑现、兑现余波；与揭示、伏笔动作和结尾钩子对应。
- [ ] 强化合同独立审阅，检查道具权限、帮助方向、人物能力、动机依据和未来揭示边界。
- [ ] 正文 Prompt 按合同执行，通过行动、对话和选择落实回报。
- [ ] 四维检查增加合同遵循、兑现落空、仅靠围观评价及重复场景功能的证据规则；保持正常概述与安静场景的合理反例。
- [ ] 合同页显示场景与读者体验信息，旧节拍按原文回退显示，作者编辑能力保留。

主要位置：`OutlineModelPromptFactory`、`WritingPromptFactory`、`WritingGenerationWorkflow`、`WritingModelOutputParser`、`WritingWorkbench.vue`；字段复用 `ChapterPlan` 和 `ChapterContractContent`。

验收：同一场景卡在合同、审阅、正文与质量输入中保持一致；失败不能以编造能力或来源修补；常规生成调用数量与基线一致；旧合同仍可读取和修改。

### B05：前三章形成统一短弧

- [ ] 强开篇策略下，大纲同时设计第 1～3 章目标、回报和钩子，逐章合同读取同一大纲版本的三章计划。
- [ ] 第一章落实具体处境、迫切问题、主角行动、阻力与第一次进展；第二章承接后果并升级；第三章完成阶段兑现并引出长线目标。
- [ ] 开头试写读取项目策略，检查仍只评估片段；不使用整章结尾或三章兑现标准误判试写。
- [ ] 对完整前三章提供连读视图：选择正文版本、展示对应合同、来源状态及已有质量问题。
- [ ] 常规路径复用每章质量检查；本地检查只判断缺章、来源和版本，不声称能判断吸引力。
- [ ] 额外模型通读作为作者主动触发的检查，调用前显示预算。必须读取三章完整正文与合同；预算不足时明确无法完整检查，禁止静默截断后显示通过。
- [ ] 连读结果绑定三章正文 / 合同 ID 与版本、大纲、策略、风格及必要依据；任一变动均失效。该扩展若保存独立报告，单独设计 API、Schema 和迁移。

主要位置：`OutlineModelPromptFactory`、`WritingContextService`、`WritingPromptFactory`、`WritingStylePreviewService`、质量用例及大纲 / 写作页面。

验收：前三章完整读下来有连续因果和第一轮回报；同型冲突重复、首章长篇背景先行、只抛问题和临时开挂能被定位；旧素材和 `OCCURRED` 章节不会自动被重写。缺章或未运行专项时显示“未完成检查”。

### B06：明确检查与修订操作

- [x] 阶段条加入“检查与润色”，区分正文质量检查与正史审稿。
- [x] 展示未检查、检查中、报告有效、结果过期、修订后需复检和主动跳过，附具体来源版本。
- [x] 允许选问题并生成新稿，展示实际修改说明，复检新稿；关闭检查保持“未检查”。

验收：旧报告不能修订新版本；有效报告选定问题生成新的 DRAFT；修订失败不覆盖原稿；作者确认与正史审批链路可完整回归；不同授权范围有对应拒绝与放行样例。
