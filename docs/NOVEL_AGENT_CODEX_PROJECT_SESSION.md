# Codex 项目会话与上下文压缩

## 当前实现

2026-10-10，在 `codex/project-session-compaction` 开发；开发前检查点为 `19c0d24`。新入口 `SIWC_CODEX` 保留已有 ChatGPT 登录、授权与凭据刷新，使用独立 Codex App Server 运行时管理历史和压缩。不自动切换现有入口，不把旧 HTTP 历史冒充 Codex 线程，不自动重跑旧失败任务。

纯文本生成与现有保存标题协议不变，模型不发送输出 JSON Schema。动态工具的参数使用协议 Schema，不属于小说输出协议。已有 DeepSeek、SIWC HTTP 和原 App Server 入口保留。

## 执行顺序

```text
作者显式选择 ChatGPT 登录 + Codex 项目会话
→ 当前账号授权检查
→ 项目会话租约（跨阶段串行）
→ 原文 / 书名 / 雪花九步 / 人物 / 方向 / 圣经 / 大纲 / 正文
  同一 NOVEL_MAIN 线程
→ 更新本轮 developerInstructions
→ 发送阶段规范、新资料与完整资料引用
→ Codex 原生历史管理、自动压缩，必要时 thread/compact/start
→ 流式公开输出
→ turn/completed 成功
→ 现有纯文本解析与同步业务回调
→ 保存已发送资料目录、释放租约
```

独立质量检查、裁决、审稿、风格样本等保留独立工作流和原有新线程策略，不让检查器依赖写作者的自我解释。正文 A 与规划共用主线程。新入口单实例也串行使用专用 OAuth 运行时，避免凭据更新重启时中断另一项目；正在运行时其他请求明确拒绝，不暗中排队或并行。

修改模板不再因为版本号变动而清空主线程；每轮通过 `thread/resume` 更新真实指令。恢复已挂载线程也更新，不提前返回。本机生成的协议定义已核对：恢复请求不发送不支持的 `dynamicTools`，工具只在创建线程时注册。

## 资料与容量

- 当前阶段职责、纯文本保存规则、作者与事实边界每轮明确发送，不转成资料引用。
- 只按服务端标题划分资料，长块以 SHA-256 标识完整原文；相同块不重复发送，修改后的块产生新标识。不用模型摘要、不按关键词删除，不改变原始数据库版本。
- 新长块超过 8,000 字符时只发送引用，明确要求先读取；已发送的相同块可以沿用上下文，需要准确引文、细节或约束时必须读回。不是保证模型一定正确遵守读取要求，文学效果仍需验证。
- `novel_read_material` 只读取本轮明确授权的标识，一次最多 6,000 字符，返回总长与下一位置。不能读取其他项目、任意文件、URL、旧未授权资料或写数据库。
- 工具补读同样消耗输入与模型时间。只减少重复发送，不保证更快、更便宜或无限上下文。
- Codex 原生 `model_auto_compact_token_limit` 由容量、安全余量和 24,000 Token 保守空间计算；未自行编写压缩摘要。当已有上下文加新输入和预留接近上限时，调用 `thread/compact/start` 并等待压缩轮次完成，不把即时 RPC 确认当压缩成功。
- 单轮实际指令、资料引用、输出预留和安全余量仍校验。指令本身过大仍会拒绝。数据库、完整正文和已确认版本才是业务依据，压缩历史不替代档案、正史或证据。

## 登录与安全

采用[官方 OAuth App Server 配置](https://developers.openai.com/siwc/token-sharing-open-source/codex-app-server)：公开 Responses provider、`env_key=ACCESS_TOKEN`、禁用 WebSocket；令牌只进入子进程环境，不进入启动参数、前端或数据库。新运行时不复制桌面 `auth.json`，不回退到 API Key 或其他账号。

凭据刷新后在无运行任务时重启专用运行时，再恢复已有线程。生成中授权变化会明确失败，不偷偷切换。运行时目录按文件所有者保护；禁用 shell、unified exec、多 Agent、应用、hooks、跨线程 memories 和 web search；只读动态工具是唯一允许的客户端工具。

会话租约每分钟续期，模型等待不持有长事务。超时、停止、网关解析或同步回调失败后解绑受污染线程，下次从数据库资料重新创建；不自动重发失败请求。旧 Codex 原始记录不删除。预检失败、尚未请求模型时只释放租约，保留原线程。崩溃后的过期租约不盲目复用未知状态线程。

当前仍是固定开发用户体系，管理口令不替代全站认证。不能无保护暴露公网。工具资料、Codex 本地记录和任务 Prompt 都是私有手稿。
