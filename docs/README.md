# 小说 Agent

HTTP 请求日志已统一记录项目 ID、请求 ID、参数／响应摘要、状态与耗时；文件／SSE 仅元信息，凭据脱敏、正文隐藏，不新增数据库迁移。重启后端加载，说明见 [HTTP 请求日志](NOVEL_AGENT_HTTP_LOGGING.md)。

面向长篇小说创作的 Java + Vue 工作台。系统以作者可控为前提，逐步完成创作意图、大纲、章节生成、正史记忆、关系图谱和一致性审查。

## 当前进度

新增“提示词管理”：顶部入口或项目设置进入，可编辑 23 个 Agent 的系统指令和阶段执行规则；导入改编/续写分开，共 25 份模板。自定义内容和历史保存数据库，支持搜索、版本冲突保护、恢复默认、历史载入及未保存提醒；后续 ChatGPT/DeepSeek 调用使用实际保存文本，历史任务与项目结果不变。需重启后端加载 V049，详见 [提示词管理](NOVEL_AGENT_PROMPT_MANAGEMENT.md)。

23 种模型工作流的实际先后关系、可选分支、作者确认门禁和返工回路见 [Agent 拓扑流程图](NOVEL_AGENT_AGENT_TOPOLOGY.md)。

写作风格新增数据库预设“校园关系：清爽叙事”：主体朴素清楚，日常互动有人情味与不同声口，感情拉扯通过小动作和话外音呈现，第一人称只保留少量机智自嘲。保存完整六维字段、八维技法、场景适配与两组原创正反例；在“大纲 → 风格试写 → 风格预设”选择，可先试写再应用，正式生成、检查与润色共用。V048 仅新增预设，不修改已有项目风格。

“故事资料 → 人物档案”已合并人物命名、作者设定、已发布底稿、规划关系、正史关系与知识、正文状态、别名和历史提及；非人物实体页只保留物品、地点、组织等。档案显示待补充设定，新增显式人物补全入口，结果先保存圣经草稿，确认发布后只补档案空白。底稿 Schema 新增性别和起点年龄，旧资料缺失兼容为空，不凭姓名或年级猜测；已有手工设定保留，未保存编辑与原行版本不会被查询刷新覆盖。无需迁移或新依赖，重启后端加载新增字段，说明见 [人物档案整合](NOVEL_AGENT_CHARACTER_DOSSIER.md)。

项目工作台顶部新增统一“生成状态”：故事方向、圣经、大纲、章节合同、合同审阅、正文、章节审稿与质量检查显示请求中／失败／成功／已停止、耗时及错误原因。生成请求发出即显示，切换标签页不丢失，每 5 秒读取后台任务，刷新后可恢复已记录的模型阶段。运行中的请求和模型任务可停止当前模型调用，保存阶段拒绝中断，未完成响应不进入产物；后端需重启加载，不保证供应商停止计费，详见 [停止说明](NOVEL_AGENT_GENERATION_STOP.md)。导入规划在保存的 GENERATING 状态下显示等待提示并禁用重复生成；模型成功与整次请求成功分别标记，不代表草稿已发布或提交正史。无新增依赖或数据库迁移，详见 [生成状态说明](NOVEL_AGENT_GENERATION_STATUS.md)。

导入页新增“原文解析”：人物、世界观、关系、事件、埋点及伏笔共用报告，逐字证据与事实／推测／未知分开。完整分段结束后，作者逐项选择保留／重构／不沿用（续写不支持重构原文），确认后才可生成圣经和大纲草稿；不自动提交正史。新增 V047，旧反推客户端需带确认报告 ID／版本。见 [原文解析交付说明](NOVEL_AGENT_IMPORT_ANALYSIS.md)。

“大纲 → 创作准备”新增串行的人物与世界设计、剧情协同和一致性检查，编辑后复检、作者确认后才用于写作。短篇可整篇准备，长篇按章节范围与剧情单元滚动，不固定以 15 万字更新。单元提交正史后可主动复核，所选未来章只生成大纲草稿，正文台账关联需另外确认；规划状态、关系与知识不提前当正史。无需新增依赖，后端重启加载 V046 后生效。详见 [创作准备交付说明](NOVEL_AGENT_CREATION_PREPARATION.md)。

Java 服务端已按合同、正文、审稿拆分写作职责，原 WritingService 保留兼容入口；运行记录、投影状态和记忆预览控制器不再直接访问数据库。新增架构回归测试，不改变 API、作者门禁或模型提示词。详见 [Java 当前架构](NOVEL_AGENT_JAVA_ARCHITECTURE.md)。

工作台“任务”页已支持章节范围自动创作：后台生成合同与审阅，等待作者确认后生成正文，再在正文确认后审稿。每章由作者确认审稿并提交正史后，任务才进入下一章。范围最多 20 章，支持持久化进度、重复请求保护、取消、显式重试和超时恢复。高级返工与费用硬上限仍在 [自动化待办](NOVEL_AGENT_AUTONOMOUS_TODO.md) 中跟踪。

新建任务可选择“正文质量检查”，页面默认勾选，已有任务保持原策略。开启后在正文草稿生成后自动检查；当前同模型报告有效时复用，正文或风格等依据变化后重检。任务页可直接打开当前章节。作者确认后进入原有正史审稿，不因确认状态变化额外重做文学检查；检查分数不替代作者门禁。

“自动语句润色”默认关闭，可选择每章最多 1～3 轮，必须开启质量检查并使用真实模型。仅当报告所有问题都是 INFO 级 FLUENCY 时自动按建议生成新稿并复检；风格、逻辑、场景及 WARNING 问题交由作者。任务生成次数上限为 1～500，默认 100；已开始、失败、超时中断的生成阶段都计数，继续任务不重置额度，自动润色至少保留一次复检额度。达到上限停止等待，旧稿和正史保持不变。此上限约束自动任务的生成阶段，不是供应商实际调用数或账单金额，也不限制作者单独发起的生成。

“大纲 → 风格试写”和“故事资料 → 写作风格”提供 11 种预设：原有现实细腻、轻快口语、悬疑克制、诗性抒情、紧凑有力，以及鲁迅（冷峻反讽）、老舍（市井幽默）、钱钟书（机智比喻）、汪曾祺（清淡烟火）、王小波（智性幽默）、余华（平实叙事）六种作家风格参考。参考预设归纳表达技法，不承诺复刻作者，不复制原作名句、人物或情节，也不能为文风改变身份、视角、事实或世界规则；也可粘贴文字或上传 UTF-8 TXT/Markdown 样本，分析为可编辑档案后由作者应用。样本长度 80～12000 字符，文件不超过 100 KB。已保存大纲（包括草稿）可用于第一章开头试写，默认约 800 字，可设置 300～1500 字；无需先确认章节合同或应用风格。最近三份试写在当前页面会话缓存中对比，刷新后不保留，明确“采用此风格”才写入项目。试写不保存为正文、不提交正史，正式写作仍使用已发布大纲与已确认合同。风格用于正文生成与质量检查，不移植样本的人物、情节和设定，人物与事实约束优先。

正文草稿可独立检查风格、通顺、逻辑和场景表达，问题必须引用实际原文。作者勾选建议后生成新的润色候选，旧稿与正史不变；正文、人物档案、风格或正史水位变化后旧报告失效。Codex/DeepSeek 负责语义分析和润色；本地模式仅提供有限规则、句式指标和版本流程验证，不提供文学质量保证。实际模型输出效果尚待评测。

已调研社区写作 skill，并从 MIT 许可的 novel-writer-skill 选择性改编文句、对话与分层修订规则，接入正文、第一章试写和质量检查 Prompt。未安装第三方脚本或自动加载器，不增加依赖，不覆盖作者风格与事实约束。详见 [调研结论](NOVEL_AGENT_WRITING_SKILL_RESEARCH.md) 和 [许可声明](THIRD_PARTY_NOTICES.md)。

写作风格页新增“根据圣经推荐风格”：从最新已保存圣经（可为草稿）分析主题、人物、冲突和叙事基调，推荐最多三种已有风格，附原文依据、适配理由与使用取舍。推荐模型可选 Codex / DeepSeek；本地模板只验证流程，不作语义适配判断。结果绑定圣经版本，源版本变化后需重新推荐；推荐、载入候选都不自动应用，仍由作者编辑、试写并明确采用。未保存的圣经编辑不参与分析，试写仍使用其大纲关联圣经。

风格不再只作为简短标签注入：正文初稿、试写、质量检查与选定建议润色共用六维执行指南，11 种规范预设补充具体技法、原创正反例及适用边界。自定义/样本分析/已编辑档案以自身字段为准，不按同名预设套用示例；通用规则不能把不同风格都压成同一种声音。STYLE 检查逐项引用正文指出偏差，润色只处理作者授权内容，不改事实或移植示例。无新增依赖或额外模型调用；原有已配置风格的质量报告需按新依据重新检查，文学效果仍待真实模型评测。

试写新增独立编辑流程：生成样例 → 检查风格、语义、逻辑和场景 → 作者勾选问题 → 生成修订样例 → 重新检查。“试写后检查”默认开启，可关闭；开启时生成后另有一次检查调用，修订和复检也各有独立调用，失败不自动重试。检查必须引用连续原文，区分真实矛盾和缺少交代，保留有作用的环境、动作和合理互助；修订优先删除、澄清，再润色，禁止编造道具来源或人物能力填补漏洞。V035 保存私有检查报告、源样例和依据指纹，每份报告只允许一次修订尝试（失败也计入），再次修改需显式重新检查。最近三份页面样例仍为会话缓存，未提供报告历史恢复界面；不覆盖原样例、不应用风格、不保存正式正文或正史。Codex/DeepSeek 执行语义编辑，本地规则不判断语义，也不能执行语义修订。流程已验证，模型识别率、误报率和事实保留效果仍待对照评测。

## 本地启动

准备 Java 21、Node.js 和 npm。后端包含 Maven Wrapper，不要求全局安装 Maven。

1. 以 `.env.example` 为模板创建 `.env.local`，填写 PostgreSQL、Neo4j 和 DeepSeek 连接信息。
2. 使用服务端 Codex 时，先确认后端进程用户已登录 Codex CLI；后端会管理 `codex app-server` 长驻进程并复用原生 thread。
3. 在 PowerShell 中从项目根目录同时启动前后端：

```powershell
.\scripts\run-all.ps1
```

   如果使用 Git Bash，也可以运行：

```bash
bash scripts/run-all.sh
```

   PowerShell 中的 `bash` 可能指向 WSL；运行 `.sh` 时请打开 Git Bash。两个服务的日志会显示在同一个终端。已有的单独启动脚本仍可用于只运行某一端：

```powershell
.\scripts\run-server.ps1
.\scripts\run-web.ps1
```

4. 打开前端日志显示的地址，默认是 `http://localhost:5173`；端口被占用时 Vite 会自动选择下一端口。后端默认运行在 `http://localhost:8081`。前端通过保留原始 Host/Origin 的代理访问后端，切换端口无需放宽后端 CORS；直接跨域访问后端时仍需配置 `APP_CORS_ALLOWED_ORIGINS`。

通过 SSH 或反向代理访问远程端口时，若转发改写 Host 导致接口返回 `403 Invalid CORS request`，可把实际页面来源加入 `.env.local` 的 `APP_CORS_ALLOWED_ORIGINS` 并重启后端。临时调试也可设置 `APP_CORS_ALLOWED_ORIGINS=*`，允许所有 IP、域名和端口；不启用跨域 Cookie 凭据。当前系统使用固定开发身份、尚无正式登录鉴权，通配符不是访问控制，勿将调试入口长期公开；生产环境使用精确来源及正式鉴权。

服务启动后可通过 `http://localhost:8081/actuator/health` 查看 PostgreSQL、Neo4j 和应用状态。

类型化正史只读接口：

- `GET /api/v1/projects/{projectId}/canon/entities`：人物、地点、物品等实体。
- `GET /api/v1/projects/{projectId}/canon/timeline`：已确认事件时间线。
- `GET /api/v1/projects/{projectId}/canon/entities/{entityId}/state`：实体当前状态及证据。
- `GET /api/v1/projects/{projectId}/canon/foreshadows`：伏笔状态。
- `GET /api/v1/projects/{projectId}/canon/entities/{entityId}/aliases`：实体的确认别名。
- `POST /api/v1/projects/{projectId}/canon/entities/{entityId}/aliases`：登记昵称、称号或旧名。
- `GET /api/v1/projects/{projectId}/canon/entities/{entityId}/mentions`：查看实体名称解析记录。
