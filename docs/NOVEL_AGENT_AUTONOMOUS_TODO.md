## 1. 当前判断

当前项目已经具备完整的可控创作主链路：

```text
故事方向 -> 故事圣经 -> 分层大纲 -> 章节合同 -> 合同审阅 -> 正文生成 -> 正文审稿 -> 作者确认 -> 正史提交 -> 长期记忆投影
```

现阶段的核心缺口不是单点生成能力，而是：

- 已有章节自动编排、多章作者门禁、限定轮数语句润色和生成次数上限；规划调度、完整审稿返工和费用硬上限仍待补。
- 已有独立正文质量检查与受控润色第一版，人物、节奏、伏笔和确定性一致性专项能力仍待补。
- 缺少修改后的影响分析、动态重规划和批量恢复能力。

## 4. P0 任务拆解

### A01 总导演 Orchestrator Agent

目标：在现有阶段之上增加一个项目级调度层。

需要能力：

- 读取项目当前故事方向、故事圣经、大纲、章节合同、正文、审稿和正史状态。
- 判断某章下一步应执行的动作。
- 调用现有用例服务，而不是绕过领域门禁直接写数据。
- 遇到阻断问题时进入等待作者处理状态。
- 记录每个自动阶段的输入、输出、耗时、失败原因和产物 ID。

建议入口：

```text
POST /api/v1/projects/{projectId}/automation-runs
GET  /api/v1/projects/{projectId}/automation-runs/{runId}
POST /api/v1/projects/{projectId}/automation-runs/{runId}/actions/cancel
POST /api/v1/projects/{projectId}/automation-runs/{runId}/actions/resume
```

验收：

- 对单章可以自动完成“生成合同 -> 生成合同审阅 -> 等待合同确认”。
- 不跳过现有作者确认门禁。
- 失败后可看到失败阶段和原因。

### A02 多章连续生成任务

目标：让系统支持按章节范围连续推进。

第一阶段建议只做到“半自动”：

```text
章节范围 -> 自动生成每章合同和正文候选 -> 自动审稿 -> 等待作者逐章确认或批量确认
```

约束：

- 不能自动提交正史，除非后续显式增加“低风险自动提交”模式。
- 每章必须使用上一章已确认或已提交状态作为上下文。
- 当前章出现 BLOCKING 问题时停止后续章节生成。
- 支持最大章节数、最大费用、最大失败次数和最大自动返工轮数。

验收：

- 能从第 1 章连续跑到第 3 章，并在每章形成合同、正文、审稿报告。
- 第 2 章能召回第 1 章上下文。
- 第 1 章出现阻断审稿问题时，第 2 章不会继续生成。

### A03 自动任务状态机

目标：把 AgentRun 从“模型调用日志”升级为“多步骤任务”。

建议状态：

```text
PENDING
RUNNING
WAITING_FOR_USER
RETRYING
FAILED
CANCELLED
SUCCEEDED
```

建议步骤表：

```text
automation_run
automation_run_step
automation_run_artifact
automation_run_event
```

验收：

- 每个自动任务能展示步骤进度。
- 任一步骤失败后可以重试安全步骤。
- 用户取消后不再发起新的模型调用。

### A04 确定性连续性规则引擎

目标：补齐模型审稿之外的硬规则。

第一批规则：

- 人物位置：同一故事时间不能同时在两个地点。
- 生死状态：死亡角色不能无解释再次行动。
- 物品持有：唯一物品不能同时被多人持有。
- 知识边界：角色不能知道未被告知、未目击或未推理出的信息。
- 时间线：事件时间不能违反已确认先后关系。
- 世界规则：硬约束不能被正文或合同违反。

接入点：

- 生成合同前：提示潜在约束。
- 审合同后：补充规则问题。
- 正文审稿后：补充规则问题。
- 正史提交前：执行最终阻断检查。

验收：

- 使用构造数据能稳定发现至少三类规则冲突。
- 规则问题与模型审稿问题合并显示。
- BLOCKING 规则问题不能被模型输出覆盖。

### A05 审稿问题自动返工闭环

目标：让轻中度问题自动进入修订，而不是完全依赖作者手动点打回。

范围：

- 自动选择可修复的 WARNING 或非高风险 ERROR。
- 组装问题证据和修订建议，调用现有正文修订链路。
- 新稿重新审稿。
- 最多自动返工 N 轮，默认 1-2 轮。

不自动处理：

- 正史冲突。
- 作者硬约束冲突。
- 实体消歧不确定。
- 需要作者判断的情节方向选择。

验收：

- 对正文中的明确小问题可自动生成修订稿并重新审稿。
- 超过轮数后进入 WAITING_FOR_USER。
- 自动返工过程保留来源审稿 ID 和修改说明。

## 5. P1 任务拆解

### A06 人物专职 Agent

第一批已实现：人物底稿随圣经版本保存，分开稳定设计、开篇状态、作者侧秘密和未来弧线；旧圣经通过显式真实模型调用补空白、创建新草稿。已有字段由程序保留，不覆盖独立人物档案，不将规划写入正史。第二批逐章变化计划和第三批连续性检查仍待开发。

目标：独立检查人物连续性和表达一致性。

检查项：

- 当前行为是否符合人物目标、恐惧、缺陷和价值观。
- 对话是否符合人物年龄、身份、关系和说话方式。
- 人物弧光是否有推进或合理停滞。
- 关系变化是否有足够事件支撑。
- 配角是否功能重复或突然消失。

输出：

```text
summary
issues[]
characterStateDeltas[]
suggestedProfileUpdates[]
```

### A07 节奏与读者反馈 Agent

目标：从目标读者视角审查可读性。

检查项：

- 开头是否过慢。
- 场景目标是否明确。
- 冲突是否足够具体。
- 信息变化是否明显。
- 结尾是否自然带出下一步。
- 类型期待是否满足。

建议与正文审稿分离，避免把“事实正确”与“好不好看”混成一个报告。

### A08 伏笔生命周期 Agent

目标：把当前正史中的伏笔记录变成主动管理能力。

检查项：

- 伏笔状态迁移是否合法。
- 是否重复埋同类伏笔。
- 是否太久未推进。
- 是否过早泄露。
- 是否回收缺少证据。
- 是否有计划回收章节但大纲没有承接。

### A09 影响分析与动态重规划

目标：前文修改后，系统能知道后文哪些内容受影响。

触发场景：

- 替换同章正史。
- 修订故事圣经。
- 修订当前写作大纲。
- 修改人物档案或硬约束。

输出：

```text
affectedChapters[]
affectedContracts[]
affectedManuscripts[]
affectedCanonFacts[]
recommendedActions[]
```

### A10 pgvector 多类型记忆分块

目标：让长篇后期召回更精准。

分块类型：

- 场景片段。
- 事件。
- 人物状态。
- 物品流转。
- 世界规则。
- 伏笔。
- 人物关系变化。

验收：

- 记忆预览能展示分块类型。
- 合同、正文、审稿阶段可以按不同权重召回。

### A11 全项目一致性扫描

目标：在已有正史上做全书级巡检。

输出：

- 事实冲突。
- 人物状态冲突。
- 时间线冲突。
- 伏笔未回收。
- 关系变化缺少支撑。
- 世界规则违反。

### A12 导入作品事实抽取提交闭环

目标：续写已有作品时，导入正文不只用于反推规划，还能形成可确认正史。

流程：

```text
导入章节 -> 抽取实体/事件/状态/关系/伏笔 -> 作者确认 -> 正史提交 -> 投影更新
```

约束：

- 素材改编模式不得自动固化原文细节。
- 正文续写模式才允许把导入内容作为已发生事实候选。

### A13 风格润色 Agent

目标：在不改变事实、情节和人物意图的前提下，提升正文的整体文风一致性。

检查项：

- 是否符合故事圣经中的叙事风格、视角和基调。
- 是否存在 AI 腔、营销腔、翻译腔、过度总结和空泛升华。
- 是否存在同一章内叙述密度忽高忽低的问题。
- 人物对白是否和人物档案中的说话方式一致。
- 修辞是否贴合人物经验和时代背景。

输出：

```text
summary
styleIssues[]
revisionSuggestions[]
polishedExcerpt
```

约束：

- 不能新增事实。
- 不能擅自改变结局、伏笔、人物关系或章节合同要求。
- 润色稿必须保留可追溯的修改说明。

### A14 句子通顺与语言质量校验 Agent

目标：做接近文字编辑的一层基础校对。

检查项：

- 病句。
- 指代不明。
- 主谓宾搭配不当。
- 重复词、重复句式和重复解释。
- 标点混乱。
- 长句失控。
- 前后语义接不上。
- 对话标签和动作描写不自然。

验收：

- 能输出具体原句、问题类型和建议改法。
- 支持只给问题报告，也支持生成修订稿。
- 不把风格偏好误判为硬错误。

### A15 逻辑正确性与因果校验 Agent

目标：检查正文内部的行为逻辑和因果链，不只检查正史事实冲突。

检查项：

- 动作顺序是否合理。
- 人物反应是否有触发原因。
- 信息从哪里来是否说得通。
- 场景转换是否缺少承接。
- 冲突解决是否过于突然。
- 人物选择是否和当前目标、代价、风险匹配。
- 段落之间是否存在因果跳跃。

与确定性连续性规则引擎的区别：

- 规则引擎检查“有没有违反已确认事实”。
- 逻辑校验 Agent 检查“这一章内部读起来是否说得通”。

### A16 流水账检测与场景化改写 Agent

目标：避免正文只是在罗列事件，而没有场景、冲突、细节和人物变化。

检测信号：

- 连续使用“然后、接着、于是、之后、很快”等顺序词推进。
- 大量概述，没有具体动作、对话、阻力和环境细节。
- 每段只交代发生了什么，没有写人物为什么这么做。
- 冲突被一句话解决。
- 情绪只用标签表达，没有可观察反应。
- 场景目标不清楚，读者不知道人物眼下想要什么。

输出：

```text
summary
flatPassages[]
sceneRewriteSuggestions[]
beforeAfterSamples[]
```

验收：

- 能定位流水账段落。
- 能说明为什么像流水账。
- 能给出场景化改写方向，而不是只说“增加细节”。

### A17 类型期待 Agent

目标：根据作品类型和目标读者，检查章节是否满足该类型的核心阅读期待。

检查项：

- 男频爽文是否有明确压迫、反击、收益和期待升级。
- 悬疑是否有线索、误导、问题推进和信息差。
- 言情是否有人物关系变化、暧昧张力和情绪回报。
- 校园、科幻、无限流、都市、奇幻等类型是否满足各自基础承诺。
- 章节是否出现类型错位，例如悬疑写成日常流水账，爽文长期没有兑现。

输出：

```text
genreFitScore
missingExpectations[]
overusedConventions[]
revisionSuggestions[]
```

### A18 黄金三章专项 Agent

目标：专项评估开篇前三章，降低读者早期流失。

检查项：

- 第一章是否尽快出现主角、核心处境和阅读钩子。
- 主角是否有可感知的吸引力、欲望、困境或行动力。
- 核心矛盾是否出现得足够早。
- 世界观信息是否过载。
- 每章结尾是否自然制造继续阅读的理由。
- 前三章是否建立清晰的类型承诺。

验收：

- 能对第 1-3 章分别输出留存风险。
- 能给出具体改法，例如前移冲突、减少设定说明、强化主角行动。

### A19 重复内容检测 Agent

目标：减少长篇中常见的重复解释、重复心理和重复场景。

检查项：

- 同一设定是否被反复解释。
- 人物是否反复表达同一种心理。
- 冲突模式是否多章重复。
- 句式、段落节奏和转折方式是否高度重复。
- 场景功能是否重复，例如连续多章都是“遭遇挑衅 -> 反击 -> 众人震惊”。

输出：

```text
repeatedItems[]
firstOccurrence
laterOccurrences[]
keepOrCompressSuggestion
```

### A20 大纲偏航检测 Agent

目标：识别实际正文与当前大纲之间的偏离，并判断偏离是否需要处理。

检查项：

- 正文是否完成章节计划中的核心事件。
- 人物状态是否偏离大纲预期出口。
- 伏笔、揭示和结尾钩子是否被遗漏或提前。
- 偏离是否是合理的自然发展。
- 偏离是否会影响后续章节合同和卷级目标。

输出：

```text
driftLevel
driftItems[]
acceptableDrifts[]
requiredReplanning[]
```

### A21 情绪曲线 Agent

目标：分析章节和卷级的情绪起伏，避免连续平淡或单一情绪压太久。

可追踪情绪：

- 紧张。
- 轻松。
- 爽感。
- 悬疑。
- 浪漫。
- 压抑。
- 失落。
- 希望。
- 危机。

验收：

- 能为每章输出主要情绪和强度。
- 能识别连续低冲突、连续压抑、爽点断档和情绪跳变过猛。
- 能给出章节级或卷级调整建议。

### A22 质量评分体系

目标：为每章提供统一的结构化质量评分，方便自动编排和人工判断。

建议评分维度：

- 连续性。
- 人物可信度。
- 语言质量。
- 逻辑因果。
- 节奏。
- 冲突强度。
- 类型期待满足度。
- 爽点或悬念。
- 风格一致性。
- 正史风险。

输出：

```text
overallScore
dimensionScores{}
blockingReasons[]
recommendedNextAction
```

用途：

- 自动任务判断是否需要返工。
- 工作台快速展示章节质量。
- 长篇回归测试对比不同模型和 Prompt 的质量变化。

## 7. 第一批实现（2026-10-03）

- 已增加 V031 `automation_run`：保存章节范围、来源大纲、模型、状态、取消请求、执行次数、等待原因及阶段记录。
- 工作台“任务”页提供创建、继续、重试、取消及阶段进度；创建请求使用 `Idempotency-Key` 防止重复启动。
- 同一项目一次只允许一个未结束自动任务；外部模型调用不占用任务数据库事务。
- 任务复用 `WritingService` 与 `QualityReviewService`。顺序为：生成合同与审阅 -> 等待作者确认合同 -> 生成正文 -> 可选质量检查 -> 等待作者选择是否润色并确认正文 -> 自动审稿 -> 等待作者确认审稿并提交正史 -> 下一章。
- 每章开始前要求上一章已提交正史；存在阻断问题、旧来源版本、大纲变化或未登记正史的已发生章节时停止。
- 取消在阶段边界生效，正在生成的候选仍留存；任务不会自动确认产物、选择事实或提交正史。
- 失败后显式重试会复用已保存产物。运行状态超过 20 分钟没有更新时，可显式恢复；执行次数校验阻止旧执行者继续修改任务。
- 当前阶段记录存于任务 JSONB，尚未拆为独立步骤、产物和事件表；尚未实现供应商调用的即时中断、自动退避重试、主动暂停及费用硬上限。有限语句返工见 V034 进展。
- 验证覆盖状态转换、阶段决策、接口校验、重试与取消，以及真实 PostgreSQL 迁移和桌面/手机页面操作。已通过本地模板两章端到端验证（8 个生成阶段、逐个作者门禁、两次正史提交）。真实模型质量评测与 20 章回归仍待补。

## 8. 设计原则

### 本次质量与风格进展（2026-10-03）

- A13～A16 共用独立质量检查 Graph，输出四维评分、逐字原文证据和建议；不是四次重复调用，也不是自动放行正史。草稿可检查，作者勾选建议生成新版本，旧稿与正史不变。
- 报告绑定正文 ID/行版本与写作依据指纹；正文、人物档案、风格或正史水位变化后旧报告失效。生成结束后再次核对，防止并发变化保存旧结果。
- A29 首版完成：五种预设、粘贴文本/UTF-8 TXT/MD 文件分析、可编辑风格档案、显式应用/恢复默认、项目版本防覆盖，以及正文与质量 Prompt 接入。不把样本当导入作品，不转移样本人物和事实。
- A29 后续补充：现为 11 种预设，新增六种作家技法参考与第一章风格试写。写作 skill 调研完成，选择性改编 MIT 文句/对白/分层修订规则，不安装外部脚本或覆盖既有业务流程；A13～A16 的实际模型对照与误报/事实保留评测仍未验收。调研与来源见 NOVEL_AGENT_WRITING_SKILL_RESEARCH.md。
- A29 圣经推荐：已保存圣经可经 Codex/DeepSeek 分析，返回一至三种已知风格与逐字依据、理由和取舍；前后校验源版本，载入候选不自动应用，本地模板不作语义判断。未实现自定义混合档案推荐、长期推荐历史或盲评验收。
- A29 风格执行强化：已增加生成/试写/检查/润色共用六维指南，11 种规范预设各有具体写法、原创正反例与场景边界；自定义及已编辑档案不按名称继承预设示例。STYLE 指明偏离维度及原文证据，通用规则尊重不同风格。仍待真实模型对照、风格辨识盲评、示例泄漏检查与修订事实保留评测，不把 Prompt 回归测试当作文学质量验收。
- A13～A16 / A29 试写编辑闭环：V035 已保存报告和源样例，独立 STYLE_PREVIEW_REVIEW 四维检查、作者选中建议后 STYLE_PREVIEW_REVISION 生成新候选并复检；单报告一次尝试，失败不自动重试，保留原样例，过期依据不能修订。同步强化正式生成/检查的细节功能、道具来源、帮助方向和最小修订约束；合理开门、授权名单、不同题互助和紧张动作作为保留对照。仍不是确定性语义校验或质量保证。
- 本地模式仅文本指标与规则检查，评分为 null；本地模板修订保留原文并明确未执行语义润色。Codex/DeepSeek 提供语义分析与润色，实际效果、误报率和事实保留仍待评测。
- 自动任务已接入可选质量检查及 V034 有限语句返工，仍不是强制质量门禁；风格混合、多档案库、多样本融合尚未实现，这些不应误标为完成。

### 自动任务质量接入（2026-10-03）

- V033 持久化 qualityReviewEnabled，旧任务及省略字段的 API 请求默认为 false，页面新建默认开启；策略进入幂等请求比较，不能同一键更改配置。
- 开启后在草稿阶段检查，复用来源 ID/行版本及依据指纹仍有效的同模型报告。报告过期则重检，检查失败恢复不重复生成正文。作者确认正文后沿用原有审稿门禁，不因确认导致行版本变化就再做文学检查。
- 任务页可直接进入当前章对应编辑页并选择任务模型；再次进入任务页会显示该任务的范围、模型和质量开关，而不是创建默认值。
- 已有单元、真实 PostgreSQL 及桌面/手机验证，覆盖策略保存、重复恢复、正文/风格/润色稿变化、取消与作者门禁。A05 的有限语句返工已进入实现，费用硬上限仍待补。

### 有限语句返工与生成额度（V034）

- 任务 maxAutoRevisionRounds 为 0～3，默认 0，必须显式开启；maxGenerationSteps 为 1～500，省略时 100。旧任务轮数迁移为 0，上限 100，既有步骤保留并计数；额度已耗尽的旧任务不再自动生成。
- 仅报告全部为 INFO / FLUENCY 时自动选择建议；风格、逻辑、场景或 WARNING 问题整份报告交由作者处理，不部分自动采纳。模型标签只是调度条件，不代表已确定证明低风险或事实不变。
- 复用 QualityReviewService.revise 的来源校验和保留事实 Prompt，保存新 DRAFT 后重新质量检查；QUALITY_REVISION 步骤保存产物 ID，正文保留基准稿和含质量报告 ID 的修改要求。作者确认、审稿和正史提交仍手动。
- 生成次数为整个任务所有已开始阶段，失败及超时中断仍消耗额度；润色轮数按当前章的已开始 QUALITY_REVISION 阶段计数，包括失败。取消/恢复/重试不重置，两项策略进入创建幂等比较。开始润色前至少需剩余两次生成额度。
- 达到额度或轮数后 WAITING_FOR_USER；保留产物，继续任务不能绕过上限，但作者可手动确认已有稿并完成门禁。费用仍为估算，生成阶段上限不能声称供应商真实调用数或金额硬上限。
- 后续仍需真实模型事实保留评测、语义风险分类、风格与场景返工、正史审稿返工、真实 usage 与任务费用归集。

### 试写编辑仍待验收

- 建立受控样例集：无作用布景、缺失道具来源、含混帮助方向及对应合理版本；由真实 Codex/DeepSeek 对照评测漏报、误报、建议可执行性和修订是否偷偷补事实。Prompt 内容断言、模板检查与受控返回值测试不等同于文学效果验证。
- 将用户反馈沉淀为通用约束与正反对照，避免按“门”“名单”“反过来”等关键词清洗，也不能把所有安静场景都改成强冲突。
- 后续再考虑报告历史浏览、样例 Diff/恢复、跨样例评价和更多细粒度人物/物品/知识约束；当前检查报告持久化不代表已有页面历史恢复能力。

### 原则

- Java 职责维护：自动任务继续通过 WritingService 的稳定入口执行合同、正文和审稿；门面内部已拆为专用服务，质量服务直接调用 ManuscriptService。此次不新增模型能力、不更改自动任务策略；架构边界由 ArchitectureTest 与数据库回归保护，详见 `NOVEL_AGENT_JAVA_ARCHITECTURE.md`。

- 不绕过作者确认门禁。
- 模型只能生成候选，不能直接写正史。
- 自动化优先串联现有领域服务，不复制业务规则。
- 自动任务必须可暂停、可取消、可恢复、可审计。
- 多章生成遇到阻断问题必须停止，不带病继续。
- 规则型检查和模型审稿并行存在，规则型 BLOCKING 优先级更高。
- 长篇质量优先依靠结构化记忆和正史事实，不依赖把全部正文塞进 Prompt。
