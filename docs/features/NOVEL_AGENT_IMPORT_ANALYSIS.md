# 原文统一解析与改编／续写交付说明

> 2026-10-05，V047。以下为当前已实现流程，真实模型解析准确率尚未评测。

## 操作流程

```text
上传原文 -> 查看章节识别
  -> 解析原文（按段串行，保存每段成功结果）
  -> 统一报告：人物、世界观、关系、事件、埋点与线索、伏笔
  -> 查看原文证据、区分明确信息／推测／未知
  -> 选择改编或续写，逐项决定并明确确认
  -> 生成故事圣经和完整大纲草稿
  -> 作者编辑并发布
  -> 大纲页创作准备（已有入口，仍由作者主动运行并确认）
```

页面入口为项目“导入”。原来的“确认并生成小说规划”改为先解析和确认报告，再启用“生成小说规划”。确认报告不自动付费生成规划，不发布圣经、大纲，不创建正文或正史。

## 报告内容

每项保存稳定标识、类别、标题、描述、相关人物、依据类型、线索进度及原文证据。

| 类型 | 含义 |
| --- | --- |
| CHARACTER | 人物身份、性格、背景、欲望、能力限制、物品、声线、状态与知识边界 |
| WORLD | 时代、地点、制度、世界规则等原文信息 |
| RELATIONSHIP | 人物关系、双方意图、各自知道的信息 |
| EVENT | 谁在何处做了什么，以及实际后果 |
| CLUE | 已出现的埋点和信息线索，不把所有道具都视为伏笔 |
| FORESHADOW | 有依据的伏笔判断；未明示的作者用意保留为推测 |

依据为 FACT、INFERENCE、UNKNOWN；作者确认不将推测升级为事实。角色传闻、猜测及不可靠叙述不能无条件当成世界事实。

FACT 和 INFERENCE 至少附一条证据，UNKNOWN 可无证据，但须说明未知，不能自动补答案。证据包含原章节 UUID、连续逐字引文及从零起算的出现序号；模型只引用本次实际提供的片段，服务端换算到整章位置。前端显示来源章、引文及周围上下文高亮。伪造引文、未知章节或越过本段实际读取范围都会拒绝保存。

线索进度包括 SET_UP、REINFORCED、PAYOFF、UNRESOLVED、UNKNOWN；非线索项使用 NOT_APPLICABLE。UNRESOLVED 仅表示该片段未见解决，不证明全文未兑现。分段报告保留独立证据，不自动按同名线索猜测合并；跨段矛盾及兑现配对需作者综合核对和后续规划模型处理。

## 改编与续写

- 改编：KEEP 保留素材核心，REWORK 根据明确备注重构（备注必填），DROP 不沿用。未来新增设计不能冒充原文事实。
- 续写：仅 KEEP 采用解析结论、DROP 不采用解析结论；后者是拒绝模型判断，不授权删除原文真实事件。禁止 REWORK，原文已发生内容仍是后续规划的约束。
- 所有项必须逐项决定，允许作者主动批量处理当前分类；不默认全部采用。确认须勾选作者确认。
- 修改处理方式、备注或切换使用模式后，前端不能用旧确认直接生成；后端验证模式、报告 ID、行版本、完整来源指纹及当前确认指针。
- 原文或章节选择变化，旧报告不能继续执行或确认；创建新报告不会自动覆盖已确认内容。另一个报告确认后，旧确认不能再作为当前生成依据。
- 现有圣经和大纲结构继续输出人物底稿、世界规则及明确读者计划；新增报告和逐项处理进入两个生成请求，草稿保存前在事务内重检来源及确认版本。

## 分段、恢复与成本

- 每个所选章节按最多 16000 个 UTF-16 字符切段，不拆开代理对，最多 40 段；创建阶段超限拒绝，不偷偷只分析前部。每段一次真实模型请求，输出参考上限 12000 Token，Codex 供应商不保证应用该上限。
- 界面显示成功覆盖段数和解析项数；必须完成所有段才能确认。覆盖字符不等于语义信息全部被正确识别，模型可漏报或误判。
- 新工作流 IMPORT_SOURCE_ANALYSIS 使用公共结构化网关和新的 Codex 会话，模型调用在数据库事务外，沿用请求审计、预算及输出观测。不支持本地模板冒充语义分析。
- READY -> RUNNING -> READY / REVIEW；失败为 FAILED，确认为 CONFIRMED，取消为 CANCELLED。成功段保留；失败不自动付费重试，明确恢复支持失败或超过 25 分钟的运行任务。
- 认领、保存和确认使用行版本及来源校验，同项目原文解析不能并发运行；取消／恢复后的迟到结果不能覆盖状态。
- 前端串行推进，离开页面不再启动下一段；刷新后可显式继续。仍是同步生成请求，不是后台无限付费队列。取消不保证供应商立即停止计费。
- 原反推规划的 80000 字符截取已移除；它使用完整所选原文和报告，超过模型上下文预算时拒绝发送。尚未实现超大原文的分层压缩规划；较大文件可能需拆分，不能因为解析完成就承诺整书规划请求一定装得下。
- 供应商在创建解析任务时记录，实际模型／强度沿用每次请求的全局设置，不是整任务参数冻结。

## 输出校验与失败详情

- category / certainty / progress 是不同维度：UNKNOWN 不是分类；非 CLUE / FORESHADOW 项的有效枚举 progress 确定性归一为 NOT_APPLICABLE，不改变事实可信度或推测内容。真正无效的分类和进度仍拒绝，不猜测它属于人物还是事件。
- occurrence 是相同完整引文在当前片段中的零基出现序号，不是段落号。引文在本段唯一逐字匹配时，服务端直接定位并换算整章出现序号；重复引文继续严格使用提供的序号，不默认选第一次，不修补缺字或编造引文。
- 独立 ImportAnalysisOutputParser 检查 JSON、必需字段和类型；失败提示保留 items 索引和证据索引、领域校验原因，不把正文或 Jackson 原始报文拼进错误提示。分段保存失败不推进覆盖进度。
- IMPORT_SOURCE_ANALYSIS 的输出解析及短事务保存纳入本次模型任务记录范围，成功保存后才记为 SUCCEEDED。校验失败记为 FAILED / OUTPUT_VALIDATION，同时保留原始响应和可得的供应商用量；不自动重试付费请求。其他生成阶段沿用旧调用方式，不改变其成功边界。
- 新代码需重启后端，不需要新迁移。已有失败记录不回填、不重新接受旧响应；作者可主动恢复解析，失败段重新请求模型，可能产生费用。

本次修复验证：后端 522 项，477 通过、45 项外部环境门禁跳过，0 失败。新增 12 项覆盖字段兼容边界、唯一／重复／伪造引文、明确错误详情、两种供应商的记录边界、失败响应及真实用量保留；本次未启用真实数据库回归、未调用付费模型，不能宣称旧响应已完整重放通过。

## 数据与接口

V047 新表 import_analysis_report 持久化来源指纹、分段范围、当前步骤、结构化内容、作者决定、确认模式、行版本和失败详情。work_import 保存当前确认报告及生成时采用的报告 ID／版本。原文件和原章节继续保留，不复制为正史。读接口经项目权限校验，no-store。

基础路径：`/api/v1/projects/{projectId}/imports/{importId}/analyses`。

| 方法 | 后缀 | 用途 |
| --- | --- | --- |
| GET | 空 / `/{id}` | 最近十份报告 / 完整报告，只读 |
| POST | 空 | 创建任务，参数 requestId、provider，不调用模型 |
| POST | `/{id}/actions/run-next` | 执行一个片段，参数 version |
| POST | `/{id}/actions/resume` / `cancel` | 显式恢复 / 取消，参数 version |
| POST | `/{id}/actions/confirm` | 参数 version、mode、decisions、authorConfirmed |

原 `actions/reverse-plan` 增加必填 analysisId、analysisVersion。旧客户端缺少确认报告会在模型调用前拒绝，不能绕过新门禁。创建用 requestId 幂等；重复键的供应商或来源不同则拒绝。确认报告和每次付费解析仍分别由作者主动发起。
