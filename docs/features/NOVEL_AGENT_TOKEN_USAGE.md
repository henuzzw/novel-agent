# 项目 Token 统计

更新时间：2026-10-13。

## 入口与口径

项目的“任务”页顶部显示“项目累计 Token”和“最近 5 小时 Token”。两个区块分别展示供应商已报告总数、实际输入/输出、本地估算总数、估算输入/输出，以及调用次数和实际用量覆盖情况。每15秒刷新，也可点击刷新任务。

- 只统计当前项目的全部 `agent_run`，不受最近100条任务列表限制，不汇总其他项目或账号额度。
- 五小时是查询时刻向前滚动五小时，以 `started_at` 为准，边界含开始和截止时刻；长调用整体归入其开始时间，不估计每个Token的发生时间。
- 成功、失败、停止和运行中的调用均参与统计，只累计当前已保存的计数；运行中的输出和供应商实际用量可能尚未保存。
- 供应商实际用量和本地估算分别相加，不能相加为“消耗总量”。未返回实际用量的调用显示覆盖缺口，不当作真实零用量；无调用时显示零。
- 估算字段为空时沿用记录中的输入/输出估算计数；不凭最新提示词或模型设置重算历史记录。
- 重试产生新的模型调用记录并独立计入，不能因为业务产物未保存就忽略已产生的调用用量。缓存及推理细分不再额外累加到输入/输出，避免重复。
- 统计不是供应商账单、剩余额度或供应商账号的固定五小时限额窗口。

## 实现

`GET /api/v1/projects/{projectId}/agent-runs/usage` 返回 `asOf`、`recentFrom`、`projectTotal`、`lastFiveHours`。两期复用现有 `AgentRunSummary` 聚合逻辑；服务层先校验项目归属，使用UTC截止时间和只读REPEATABLE_READ事务，保持两期同一数据库快照。响应禁止缓存。不读取正文、提示词或调用模型，无数据库迁移和新增依赖。

11项后端定向测试（含只在PostgreSQL临时表验证范围与边界）、4项前端测试、类型检查及相关ESLint通过。覆盖其他项目隔离、超过100次调用、五小时边界、未来记录排除、失败/停止用量、缺失实际用量和空项目。后端重启后启用。
