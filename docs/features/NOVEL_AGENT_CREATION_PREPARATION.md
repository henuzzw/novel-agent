# 创作准备与剧情单元复核交付说明

> 2026-10-05，V046。本文描述已实现的业务闭环，不代表真实模型文学质量已验收。

## 设计原则

不以 15 万字作为固定更新周期。篇幅用于大纲字数预算，资料设计以章节范围、剧情单元及其结束条件为边界。短篇可覆盖整篇；长篇由作者选择当前范围，随单元结束复核，再为后续范围准备资料。现有逐章审稿和正史提交负责实际变化，不需要等到某个字数门槛。

5 万字作品示例：先发布整篇大纲，创作准备默认覆盖所有尚未进入正史的章节；模型将它划成连续、无重叠的剧情单元。单元可以按冲突、转折、阶段目标和结束条件划分，不强制每单元章数或字数。示例中的 20 章不是系统固定值。

## 页面操作

1. 发布故事圣经和大纲，打开“大纲 → 创作准备”。
2. 选择“创作准备”，默认范围是最后正史章之后到大纲末章；也可显式指定范围。
3. 点击生成，页面串行执行人物与世界设计、剧情协同设计、一致性检查三个模型步骤。
4. 查看、编辑人物、实体、初始状态、剧情单元、关系、知识边界、时间线和读者承诺计划。保存修改会清除旧报告，必须重新检查。
5. 阻断问题不能直接确认；警告须明确接受，作者勾选确认后才能应用。
6. 合同、正文、审稿、质量检查/修订及风格试写读取适用的已确认准备资料。仍走原来的正文确认、审稿和提交正史流程。
7. 单元内各章提交有效正史后，页面提供“复核此单元”；点击才调用模型，不自动收费。
8. 复核的未来章调整由作者逐章选择，确认后生成新的大纲草稿，通过原大纲页面编辑和发布。
9. “伏笔与承诺”展示复核产生的正文事实与计划关联建议；另行勾选并确认登记，才生成原台账的进展事件。

## 实际流程

```text
已发布圣经 + 已发布大纲 + 人物档案 + 台账 + 有效正史
  -> 创建冻结来源的任务
  -> 人物与世界设计
  -> 剧情协同设计
  -> 一致性检查
  -> 作者编辑 / 重新检查 / 明确确认
  -> 规划资料同步 + 写作上下文
  -> 合同 -> 正文 -> 质量检查与受控修订 -> 审稿
  -> 作者确认接受事实 -> 提交正史
  -> 剧情单元复核（作者主动）
  -> 未来大纲草稿 / 台账关联建议（分别确认）
```

复核模式只运行一致性检查，不重新运行前两步。新增工作流是 `CREATION_PREPARATION_WORLD`、`CREATION_PREPARATION_PLOT`、`CREATION_PREPARATION_REVIEW`，每步使用公共模型网关和新的 Codex 会话，沿用请求审计、预算校验和响应观测；不支持本地模板冒充语义设计。

## 数据和事实边界

| 内容 | 保存和应用方式 |
| --- | --- |
| 完整人物蓝图 | 任务 JSONB；确认后建立稳定规划身份，独立档案只补空白 |
| 实体、物品、地点、组织 | 任务保存完整设计；确认后新增规划实体，不创建正史事实 |
| 初始状态、物品所属与变化计划 | 保存在规划设计中，不写入实际状态表 |
| 初始及未来人物关系、知识边界、时间线 | 保存在规划设计中；关系页分区展示，适用章写作输入明确标注未来计划 |
| 新伏笔与承诺 | 明确结构化种子，确认后来源为 `PREPARATION` 的共享台账计划 |
| 已发生的状态、关系、知识、时间线 | 继续由接受审稿事实并提交正史产生 |
| 未来大纲调整 | 只允许最后正史章之后且非 `OCCURRED` 的已有章；保存新 `DRAFT`，不自动发布 |
| 正文与计划关联 | 引用有效正史伏笔事实和逐字证据，保存建议；另外确认后才登记进展 |

既有人物档案的非空稳定设定优先，不允许模型通过本任务偷偷改掉。需要修改这类设定时，使用原圣经或人物档案修订入口，再创建新准备任务。作者秘密不等于角色知道，当前实际状态不等于开篇状态。

每个项目保存一个当前已确认准备任务指针。新准备替换当前指针，旧任务和旧台账进展仍保留，旧来源标记替换；不是同时叠加所有历史规划。当前圣经或大纲改变后，旧准备不能继续作为新来源使用。

## 来源、状态和失败处理

- 任务保存来源圣经、大纲、项目策略、创作意图、人物身份/档案、台账、所选范围正史摘要和接受事实、前两章摘要、当前实际状态/关系/知识及已有准备设计。
- 输入和输出检查不静默裁掉完整准备资料；超模型预算拒绝发送，作者可缩小规划范围。当前实际知识等结构化数据仍可能较大，未实现全量智能压缩。
- 正文输入读取当前单元引用或本章到期的准备台账计划完整内容，以台账当前行版本为准；作者编辑和软删除即时生效，不从旧任务快照恢复计划内容。
- 创建用 `requestId` 幂等，相同键但不同参数拒绝；修改、执行和确认使用任务行版本。
- `READY -> RUNNING -> READY / AWAITING_CONFIRMATION`；错误进入 `FAILED`。取消进入 `CANCELLED`，作者确认进入 `CONFIRMED`。
- 模型在数据库事务外运行；认领、阶段保存和确认在短事务中校验行版本和来源，取消后的迟到结果不能覆盖任务。
- 失败不自动付费重试。显式恢复支持失败任务，或超过 25 分钟仍处于运行状态的任务；来源已变化则拒绝恢复。
- 前端按步骤串行请求，关闭页面不自动继续下一步；生成请求仍同步等待，不是后台 202 持续创作队列。
- 取消仅保证业务状态隔离，不保证立即中断供应商或停止计费。
- 每个出站请求冻结本次实际模型配置，后续步骤仍读取该供应商当前的全局配置，不是整任务模型参数冻结。
- 问题必须引用来源中的逐字证据；阻断项不能用接受警告绕过。语义正确性仍取决于模型和作者复核，程序校验不是因果正确性的证明。
- 单元复核绑定当前正史水位；水位变化会要求重新核对，不自动证明历史报告仍有效。到期提醒是规则提示，未登记兑现不等于正文没写兑现。

## 接口

项目私有路径：`/api/v1/projects/{projectId}/creation-preparations`。

| 方法 | 后缀 | 作用 |
| --- | --- | --- |
| GET | 空 / `/{id}` | 最近任务 / 完整任务；只读、`no-store` |
| POST | 空 | 创建 `PREPARE` 或 `REVIEW`，不调用模型 |
| POST | `/{id}/actions/run-next` | 显式执行下一步 |
| POST | `/{id}/actions/run-all` | 同步串行至多三个步骤，失败停止 |
| PUT | `/{id}` | 保存完整 `world`、`plot`，旧报告失效 |
| POST | `/{id}/actions/resume` / `cancel` | 明确恢复 / 取消 |
| POST | `/{id}/actions/confirm` | 作者确认应用或生成未来大纲草稿 |
| GET | `/checkpoints` / `/plan-links` | 剧情单元节点 / 关联建议 |
| POST | `/plan-links/{id}/actions/confirm` | 另行确认关联并登记台账进展 |

创建参数：`requestId`、`mode`、`provider`、可空的 `startChapter/endChapter`、`instruction`。执行/恢复/取消参数：`version`。保存参数：`version/world/plot`。确认参数：`version/authorConfirmed/acceptWarnings/selectedChapters`。关联确认参数：`requestId/planVersion/authorConfirmed`。应用前重新校验来源；计划修改、事实撤回或正史替换会让旧关联失效，登记仍复用原台账的逐字正文证据和合法状态转换校验。
