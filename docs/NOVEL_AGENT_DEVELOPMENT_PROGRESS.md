## 5.1 本轮完成：作品导入、Embedding、图谱和任务成本

### 已有作品导入

- 原始文件以二进制保存，并记录文件名、媒体类型、大小、SHA-256 和解析器版本。
- 支持 TXT、Markdown、DOCX 和文本型 PDF，单文件上限默认 20 MB。
- 自动判断正文、大纲或设定资料，按章节标题切分；无法切分时保留全文并给出明确警告。
- 导入结果先进入待确认区，不直接污染正史；作者可预览章节、下载原文件并确认报告。
- 已使用工作区现有 Markdown 实测：识别为正文，3075 个字符，因原文无章节标题而生成单章警告。

### 导入内容生成小说规划

- 作者确认导入报告后，可选择服务端 Codex 或 DeepSeek，一次操作连续生成故事圣经草稿和分层大纲草稿。
- 作者必须明确选择导入用途：“故事素材改编”允许扩写、重构、优化和改变，全部章节从第一章开始待创作；“已有正文续写”才把导入内容作为已经发生的历史。
- 正文续写模式把原文视为不可改写的既有事实，无法确定的信息进入“待作者决定的问题”；素材改编模式只保留核心吸引力和作者硬约束，不把原文细节自动固化为正史。
- 大纲章节显式标记为“已发生”或“待规划”。已导入正文对应“已发生”，后续续写章节对应“待规划”。
- 服务端按导入章节数确定性归一化章节状态；模型生成章节不足时拒绝保存，不只依赖 Prompt 标记。
- 反推结果只创建新草稿，不发布故事圣经或大纲，也不修改项目当前版本指针和正史。
- 故事圣经版本记录来源导入 ID；导入记录保存反推状态、产物 ID 和失败原因，便于追踪与重试。
