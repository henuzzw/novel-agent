# 模型请求架构与资料去重

2026-10-10。此次调整只改请求层，不增加文学 Agent、不改变模型纯文本返回、不覆盖数据库里的提示词配置或小说版本。

## 职责划分

```text
规划 / 导入 / 写作 / 检查业务 Agent
  → StructuredModelGateway：一次读取配置、选择入口
  → ModelPromptAssembler：解析配对模板、阶段规则、业务边界及资料
  → AbstractModelExecutor.execute：公共生命周期
      ├── LegacyCodexExecutor：旧 Codex App Server
      ├── ProjectCodexExecutor：ChatGPT 登录 + Codex 项目会话
      ├── DeepSeekExecutor：DeepSeek
      └── ChatGptHttpExecutor：保留原 HTTP 直连入口
```

执行器采用模板方法，execute 不允许子类覆盖。认证、会话、材料存储仍通过组合调用已有组件，不搬进抽象类。旧业务调用方法保持不变，不需要每个 Agent 重写路由。

## 统一流程

1. 冻结当前提示词版本、业务边界和选定模型参数；公共组装层读取当前已保存作品书名，明确标为故事数据直接发送。书名仅辅助定位与读者期待，不覆盖事实、阶段职责、作者授权或风格。自动命名前的占位名不传，BOOK_TITLE自身不传旧名；短书名置于长资料引用范围之外，始终保留内联，不依赖会话记忆。无额外模型请求或JSON返回变化。
2. 各入口准备本轮真实发送的指令及上下文。
3. 校验真实输入、输出预留和安全余量；HTTP 入口额外保留完整历史预算。
4. 记录真实 System / User 输入和快照，不用未去重的原始输入冒充发送内容。
5. 调用当前入口，保留现有公开响应进度、停止和错误处理。
6. 纯文本解析后执行同步业务保存回调。
7. 仅解析和业务保存均成功后确认会话或资料发送状态。
8. 成功、容量超限、请求失败、解析失败、保存失败均释放已获取资源。

未启用的入口或认证失败明确报错，不自动切换模型、账户、计费或传输。底层超时、流式和中断机制仍由原客户端实现，DeepSeek 当前仍非流式，此次未将它改成流式。

## 旧 App Server 去重范围

- 只处理服务端“本轮创作资料”之后的内容。阶段职责、输出保存协议、事实边界始终直接发送。
- 整段 JSON 资料、明确标题后的 JSON、已知雪花底稿区块及书名原文可以按精确内容寻址；不做语义摘要。
- 小于 1,000 字符的资料仍直接发送；首次资料不超过 8,000 字符时直接发送，成功后相同版本可以引用；首次更长资料以完整文件提供并要求先读。
- 完整资料存于原项目工作目录 `.novel-materials/<SHA-256>.txt`，按文件所有者保护，原始数据库版本不变。保存校验标识与文本相符，拒绝路径符号和资料目录/目标文件符号链接。
- 指令、作者要求、未识别边界和可能混有结尾指令的原文区块保守保留。不是所有冗余文本都已消除，也未实现各阶段语义相关性筛选。
- 缓存按项目、工作流绑定和确切线程隔离；线程切换不能沿用旧线程的已发送目录。请求或保存失败后清除该缓存，下一轮保守重送。缓存不持久化，后端重启后首次符合条件的资料也会重送。
- 项目内不同工作流使用同一进程锁，防止同时操作旧线程；不是跨实例租约。旧入口按单后端使用。
- 不为去重重建旧线程或更换账号。`thread/start` 注册动态工具；安装版本的 `thread/resume` 不支持追加 `dynamicTools`，恢复时从原生会话文件的首条元数据核对工具定义是否已持久化。没有该能力的旧线程不使用文件引用，改为完整发送本轮资料。
- 两条 Codex 入口共用 `novel_read_material(material_id, offset)`：每页最多6,000字符，返回总长度、下一页位置与原文。旧入口只允许本轮授权的SHA-256标识，对项目私有文件校验真实路径、符号链接和内容指纹；新入口保留原账号/租约范围。任务结束关闭授权范围，不提供任意路径、文件写入或跨项目读取能力。
- 接近容量时等待原生压缩完成再生成；原生压缩不替代数据库人物、正史或逐字证据。工具读取也消耗上下文和时间，不保证速度或账单下降。
- 未验证真实模型一定正确读取文件、保持事实或遵守风格。失败轮次不会自动回退、分叉或删除旧 Codex 历史。

### 2026-10-11 资料读取与失败恢复

不能以提示词中的“请读取文件”代替真实工具注册。本次明确注册工具、处理底层调用与结果，验证完整分页原文、授权范围和线程恢复；不依赖模型能调用原生终端。
