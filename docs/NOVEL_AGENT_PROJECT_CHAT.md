# 项目创作对话

## 当前能力

项目菜单中的“创作对话”用于了解资料、讨论调整，并形成可确认的修改候选。路由为 `?section=chat`，刷新保留当前页面；后台对话和候选保存在数据库。

流程：作者提问 → 按需读取或检索 → 回复与修改候选 → 作者查看修改前后、理由及影响 → 确认应用或不采用 → 保存新版本。已应用修改可以撤销，但来源已经被再次修改时拒绝覆盖。

## 资料与修改范围

- 可读取导入原文、雪花底稿、人物档案、大纲、最近正文、伏笔承诺和已确认规划资料。
- 可提出人物档案字段、雪花步骤和大纲章节文字块的修改；同轮同版本的多个字段或章节作为一组确认、拒绝及撤销。
- 雪花每轮只改一个步骤，保留有效前缀，清除依赖它的后续步骤并保存新运行。作者随后继续生成、重新确认，不覆盖已确认规划快照。第7步统一人物投影只读，人物调整通过独立档案完成。
- 大纲保存新草稿，不自动发布；所修改章节之后的待创作章节标为待更新，已发生章节不可修改。
- 正文、原文、有效正史和确认资料只读，不自动重写、批准或提交正史。人物档案改动不会自动改写圣经硬约束或已确认正文。

修改前需要完整读取目标，并冻结目标版本与项目依据。应用和撤销都重新核对项目归属、版本及当前来源；不允许覆盖作者在对话之后做出的修改。撤销通过新版本恢复，不删除历史。

## 模型与工具

使用全局选择的供应商，工作流 `PROJECT_CHAT` 与主创作会话隔离；两条 Codex 入口复用独立对话会话，DeepSeek 每轮发送当前必要历史及工具结果。纯文本返回保持不变，系统提示词和阶段提示词可在提示词管理中配对编辑。

`READ`、`SEARCH`、`PROPOSE`、`REPLY` 是应用层工具循环，模型通过纯文本保存标题返回动作，服务端解析后执行；不是新增供应商原生工具协议。`READ` 分页读取当前授权目录，`SEARCH` 复用关键词、向量与 Neo4j 只读记忆检索，`PROPOSE` 仅暂存候选，最终 `REPLY` 成功后才保存供作者选择。模型没有应用、数据库写入、文件写入或正史发布工具。

每轮最多16次动作、5个不同修改目标；资料每页6000字符。单个项目只允许一个运行中的创作对话。支持停止；失败或停止不保存未完成候选，不自动重试。后台重启遗留任务标失败，作者手动重新发送。

页面显示请求状态、资料引用、完整修改前后文本、影响范围及确认/拒绝/撤销按钮。回复当前在完成后展示，不宣称流式正文输出。历史接口展示最近100轮和100条修改；数据库仍保留更早记录，暂未提供分页浏览。

## 数据与接口

V061 新增 `project_chat_turn`、`project_chat_change`。不修改现有正文或正史记录。

接口前缀：`/api/v1/projects/{projectId}/chat`。

| 接口 | 用途 |
| --- | --- |
| GET /turns | 最近对话与状态 |
| POST /turns | 幂等提交问题，后台执行 |
| POST /turns/{id}/stop | 停止对话 |
| GET /sources | 当前资料目录 |
| GET /source?key=...&offset=... | 当前资料版本分页预览 |
| GET /changes | 修改候选及状态 |
| POST /changes/{id}/apply | 作者确认同组候选 |
| POST /changes/{id}/reject | 不采用同组候选 |
| POST /changes/{id}/undo | 来源未被再次修改时撤销同组修改 |

所有接口校验项目归属。检索来源是参考证据，未命中不意味着资料一定不存在；候选设计不自动变成事实。

## 验证

定向验证覆盖工具权限、完整读取、停止、空检索、纯文本协议，以及隔离 PostgreSQL Schema 下的候选确认、组合修改、版本冲突、越权和撤销。浏览器验证采用模拟接口，未对真实项目发起模型生成或写入。
