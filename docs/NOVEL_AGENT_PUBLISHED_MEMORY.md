# 发布后记忆整理与默认接受

更新：2026-10-14。

## 自动落库与作者管理（当前）

已发布正文 → 大模型提取本章实体、事件、状态、关系、认知及伏笔 → 原文证据与实体引用校验 → 同一事务整批落库 → 下一章生成。

新任务不再以“部分自动接受、部分待确认”结束。所有有效条目自动保存；引用无法解析、输出无效或落库失败时整批回滚，记忆任务为FAILED，并保留通过证据校验的候选供作者修正。不会自动接受不明身份、伪造ID或缺失引文。视角定位资料随请求提供，只帮助绑定第一人称，不把规划事件当作记忆。物品、地点等允许有依据的描述性名称，不要求名称逐字出现在引文中；新人物和组织仍须有姓名依据。

作者在发布后记忆页面查看、编辑、新增、移除或恢复条目；正常自动整理无需作者逐项操作。PUT commit/{id}/memory 校验项目、当前有效提交、记忆行版本和本章原文证据，保存前的条目保留在canon_memory_history。移除以REJECTED记录，不改正文；修订退役旧事实与派生状态、关系、知识、伏笔，保存新记忆并通知可重建投影。来源实体身份可能被其他章节使用，不随删除一条记忆而删除人物。

自动推进开启记忆时，必须等所有相关前文记忆SUCCEEDED，FAILED、NEEDS_CONFIRMATION及缺失任务不会放行。新创作在请求模型前再次核对；现有正文读取、手动检查和局部表达修订不被当作下一章创作。显式关闭记忆的SKIPPED仍是作者选择，但不代表已完成提取。

人工修改或重新整理旧章记忆会提升正史索引水位。已经在修改前发布的后续正文保留，但不能再默认沿用来继续生成；生成入口提示最早受影响章节，不自动重写或重跑。相关事实直接从PostgreSQL权威记录召回，按项目、章节及版本过滤，不依赖Neo4j消息是否已到达；图谱同步清除旧派生版本，过期投影不会代替权威事实。

V063只新增修改历史表，不自动处理存量待确认任务、不发起付费生成、不重写正文。历史待处理任务可由作者点击重新整理，或在编辑页面修正引用后保存；失败不会自动付费重试。

## 历史流程

正文草稿 → 质量检查／修订（可跳过）→ 作者确认并发布 → 后台记忆整理 → 后续章节检索。

“正文质量检查”处理风格、语句、逻辑及场景节奏；“发布后记忆整理”只抽取已发布正文中的实体、事件、状态、关系、人物认知和伏笔进度，不评分、不要求返工、不修改正文。任务列表、生成状态与写作标签使用统一名称，内部阶段标识仍为 `CHAPTER_REVIEW`。

## 默认接受

发布即授权从该正文建立可追溯的记忆索引。六类条目通过逐字正文证据、类型和编号校验，并且引用可定位后，后台直接保存为 `ACCEPTED`，写入事实及对应投影并发出投影更新事件，不需要作者逐项选择接受。

不再限制为极少数事实类型，不要求模型置信度达到0.95，不要求概括后的主谓宾和摘要逐字出现在引文中，也不使用中文关键词判断事实是否可接受。省略置信度仍可接受；非法数值仍拒绝。语义抽取遵守现有提示词：猜测、传闻、谎言及未来安排不能冒充客观事实，知识条目保留人物认知与真实性标签；本次没有新增语义模型检查调用。

实体解析遵守既有物化顺序：项目目录中的明确ID → 当前名称 → 已确认别名。新具名实体须出现在正文证据中，允许在物化时创建。未定位的代词、多对象同名／别名、无效或跨项目ID、类型不符及生成期间已有实体身份变化，仍保留为 `PENDING`，不能随意绑定。

其他有效条目照常自动接受；确有待消歧条目时显示“部分记忆待消歧”。已接受条目只显示结果，不再显示逐项接受选择。待处理条目预选“接受”，作者只需选正确实体、一次保存；也可拒绝或暂不处理。预选不会自行发送写请求，也不把页面初始值视为未保存作者编辑。

记忆列表使用独立的纵向布局：事实内容、完整引文、实体消歧与处理结果逐行展示，不复用旧审稿的双列样式。引文保留换行，长文字自动折行；窄屏实体选择也改为上下排列，避免引文挤进右侧窄列。布局回归覆盖宽屏和窄屏，并确保查看页面不发送写请求。

## 保留的边界

- 引文不存在、重复编号或无效类型等输出错误仍使整理失败，不伪造证据，不保存为有效记忆。
- 保存前核对当前发布提交仍有效，已被新版替换的正文不写入记忆。
- 原有项目行锁、记忆任务状态锁、行版本守卫、原文不可改写及已处理条目不可覆盖保留。
- 正文发布不等待记忆整理，整理失败不撤销发布；失败重试仍由作者手动发起。
- 不自动回填旧任务、不重跑模型、不重写历史正文，无数据库迁移或新增模型调用。

定向验证覆盖六类默认接受、具名新实体、代词消歧、关系双方、无效ID、名称优先于别名、并发身份变化、原文证据、后台物化和发布替换门禁，以及前端默认选项和批量保存。后台策略需重启后端加载，前端热更新即可。
