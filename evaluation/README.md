# 写作回归与对照评测

## 当前交付

语料位于 [writing-corpus-v1.json](D:/project/agent/novel-agent/apps/server/src/test/resources/evaluation/writing-corpus-v1.json)。包含四类固定圣经、人物档案和完整风格档案，26 个短场景（13 对问题 / 合理反例），以及关系驱动、悬疑信息驱动、强情节行动驱动三组完整微型三章，共 9 个短章。

三章样例为每章 200～600 字的完整微型故事，不是开头片段，但也不代替番茄常规长度章节的留存评测。B05/B07 还需加入常规长度三章、目标读者盲评及真实模型多次生成。

覆盖：道具权限、帮助方向、关系越界、空喊悬念、认知泄漏、时间因果、重复动作、流水账、风格错位、临时开挂、只靠围观评价的假回报、主语指代；合理反例保护普通道具、跨科互助、有限关系进展、具体线索、误认、安静场景与必要概述。

`WritingEvaluationBaselineTest` 通过真实 `WritingGenerationGateway -> WritingModelRouter` 截取 44 份请求：26 份场景质量检查、9 份正文生成、9 份短章质量检查。公共外部网关和输出解析器使用测试替身，人物 / 风格服务提供固定夹具；提示词、Schema、输出上限与 Codex 会话策略均来自现有实现。没有数据库、网络、密钥或新依赖，也不执行任何模型生成。

## 导出基线

在 `apps/server` 目录运行，输出目录必须尚不存在：

```powershell
.\mvnw.cmd -q test '-Dtest=WritingEvaluationBaselineTest,WritingPromptRevisionTest,PlanningPromptConstraintTest' '-Dnovel.evaluation.output=../../evaluation/runs/current-v1'
```

不传 `novel.evaluation.output` 时只执行验证；显式导出用例会跳过。修改模板前先导出 `current-v1`，修改后用新目录导出 `candidate-v1`。禁止覆盖旧基线。

导出目录：

| 文件 | 内容 |
| --- | --- |
| `manifest.json` | 语料版本、语料及各请求 / 输入 / 提示词 / Schema 的 SHA-256，截取模式与零供应商调用说明 |
| `requests/*.json` | System / User、Schema 名称与结构、输出上限、会话策略、完整规范化输入 |
| `corpus.json` | 当次原创语料原始快照，包含人工标签，仅供评测管理 |
| `labels.json` | 人工问题、反例、最小修改边界及三章评估标准，不得传给模型 |
| `results-template.json` | 每请求的未运行记录，未知模型、耗时、调用数和 usage 均为 null，不伪装成零用量 |

场景名称中的“问题 / 正常”信息不会成为正文标题；正文生成看不到当前参考正文，只看到合同和前章固定原文。前章标为作者确认、未提交正史。此处是固定输入实验，不测实际召回、裁剪或模型配置快照。规范化合同与单卷大纲由语料确定性组装后冻结，不能视为经过作者审批的数据库产物。

`requests.input.memory.usage` 是离线夹具元数据，`OFFLINE_FIXTURE` 不代表供应商或真实预算测量。对照时先核对 `inputSha256` 一致；若风格执行指南或上游输入也变动，必须登记为输入变化实验，不将结果归因于单独的 Prompt 优化。

## 真实模型对照协议

1. 先登记供应商、实际模型、推理强度（不适用则 null）、重复次数、最大请求数 / Token 预算、上下文上限和停止条件。尚未选择时保持未知，不能用全局默认值补充“实际参数”。
2. 按相同输入、模型配置、输出上限比较当前和候选。仅发送请求的 System / User 与 Schema；不发送 `labels.json`、语料标签或参考答案。新线程规则保留。B01 不提供绕过项目权限和版本校验的外部调用器。
3. 每次尝试独立记录 `sampleIndex`。`effectiveModel` 保存实际 provider、model、effort 和必要参数；记录开始时间、耗时、真实调用次数、原始输出路径和失败类型。超时 / 鉴权 / 限流不能假装为格式错误或悄悄重试。
4. `usageKind` 使用 ACTUAL / ESTIMATED / UNKNOWN。没有供应商 usage 时保持 UNKNOWN；估算与实际分开，不从字符数推导真实费用。失败也计入实际调用预算。
5. 输出先经过现有领域解析器，检查质量证据是否逐字存在；这一步只证明结构和证据合法，不证明建议正确。场景人工复核目标问题是否命中、反例是否误报、建议是否新编事实。
6. 给评审的正文只标随机候选编号，隐藏供应商、模板、评测标签及文件来源；编号映射另存，评价完成后解盲。每维记录 1～5 分或无法判断，并附原文、原因、是否继续读、弃读位置、事实变更与修订越界。
7. 三章生成先用相同固定前文做逐章对照，再另做生成稿串联实验。固定前文实验不能证明真实连续创作质量。连读评审重点检查第 1 章问题与进展、第 2 章后果、第 3 章有铺垫兑现，不将抛问题数量或喝彩句数当成吸引力。

结果表模板见 [评测记录模板](D:/project/agent/novel-agent/evaluation/RESULT_TEMPLATE.md)。运行产物位于 `evaluation/runs/`，默认不进入版本控制，避免把将来真实模型输出或私有资料误提交。

## 验证边界

自动测试验证语料完整性、正反例配对、输入来源与标签隔离、请求可重复性、证据解析和导出防覆盖。语料与初始标签由本轮编码助手整理，供人工复核，不是外部读者共识。部分场景对齐现有 Prompt 中已出现的编辑例子，只能检验回归，不能证明泛化；B07 需加入不进入 Prompt 的独立留出语料。真实模型请求、质量命中率、修订事实保留、常规长度三章及读者留存尚未验证；不能据此宣称文学质量已改善。
